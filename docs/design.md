# 设计取舍

目标是让 AI 能找到复杂配置的可复用做法，判断它是否适用于眼前环境，
在中断后安全继续，并把使用中得到的新知识回写到同一个维护入口。

## 保留的基础

| 设计 | 对长期使用的作用 |
|---|---|
| catalog.jsonl + 短 SKILL.md + operation references | 先查目录，再按需读取，控制上下文成本 |
| 稳定技能 ID、自包含资源和锁定依赖 | 可独立携带技能，降低从聊天历史重建配置的成本 |
| 操作契约及显式验收项 | 区分安装、诊断、验证与回滚，减少错误扩展任务范围 |
| sources、evidence 和 limitations | 区分事实出处、实际验证、未验证分支 |
| 源码与运行状态分离 | 避免将凭据、机器备份或一次执行结果混成通用知识 |
| 本地校验及公共合成 CI | 在不使用真实账号的条件下检查结构、脚本和基础行为 |

这些基础足以支撑当前规模，无需引入数据库、向量搜索或执行服务。

## 已补齐的结构

| 原有缺口 | 当前约束 |
|---|---|
| 已有诊断错误码不一定可检索；ID 拆词会匹配泛化的 gateway | 维护明确别名、精确英文边界；finding 别名也参与检索 |
| 目录只有状态标签，看不见适用环境和未解决问题 | 目录投影包含平台、当前证据日期/范围和 open findings |
| 使用后没有一致的纠错入口 | AGENTS 和技能入口要求反馈检查；每包有 findings，维护指南规定处理流程 |
| 只有文字说明，无法阻止未闭环的问题被当成已解决 | schema 和引用检查约束关闭依据；blocking open finding 禁止 active |
| 历史材料哈希必须永远等于最新文件，阻碍正常升级 | current 校验当前材料；historical 保留旧事实，允许材料升级或删除 |
| 私有 run schema 未绑定操作契约和实际技能版本 | 内容哈希覆盖未提交改动；检查器验证操作必需验收及反馈引用 |
| 新技能被强制要求无关的 HTTP/CLI 超时 | 通用重试/停止边界保留，具体请求或 CLI 超时按需声明 |

首个技能将环境说明放在字符串 metadata 和 contract.dependencies.platform 中，
以兼容本机附带的技能快速校验器（其顶层字段白名单不含 compatibility）。
仓库验证器仍接受顶层 compatibility；这是一项客户端兼容处理，不是对格式规范的否定。

维护步骤见 [maintenance.md](maintenance.md)，这里仅记录结构与取舍，不保存私有运行历史。

## 能保证什么

执行 `npm run validate` 和 CI 可以发现结构缺失、悬空引用、目录漂移、当前证据
哈希失配、未分类证据和 active 技能中的 blocking open finding。
`check-run` 可以拒绝与当前技能不一致或遗漏操作验收项的私有记录。
自动检查不能证明一条 source 或人工验收描述真实，也不能证明模型实际遵循了指导。

每次使用的反馈要由客户端显式执行。技能在其他机器或不读取 AGENTS 的客户端中
使用时，仓库无法自动知道发生了什么；因此技能入口也保留反馈要求。
要实现自动采集，需要另行设计客户端接入、私有存储及用户授权，当前不引入。

active 表示声明范围内可复用。历史安装、当前离线检查、当前目标环境的 live/UI
验收互不替代；搜索返回候选也不代表环境兼容或执行许可。

## 后续扩展时的判断依据

- 先积累真实搜索失败用例，维护别名和回归测试；技能数量或查询变化再决定
  是否引入全文/语义索引，保留可解释的候选和适用范围。
- 多个技能出现同一种稳定结构后再抽取共享契约，避免用网关特例定义所有技能。
- 重要升级通过 finding、来源和新证据留下依据；无需为每次文字编辑复制变更日志。
- 内容哈希有意保守：文档或反馈记录变化也会要求续跑审查。它用于防止盲目复用旧状态，
  不是兼容性版本号；未来确有需要时可在此基础上增加显式兼容性规则。
